# LiteLLM 用户认证审查记录（2026-09-22）

审查范围：`codex/litellm-user-auth` 的客户端换证与 OpenClaw 凭据交接、
JWT Hook、首次自动入组、Team 管理、旧版 Key 迁移及部署配置。
三名独立 Agent 分域审查，主 Agent 复核并统一回归；源码对照 LiteLLM v1.99.1。

## 已确认并修复

| 风险 | 问题 | 修复与回归 |
| --- | --- | --- |
| 高 | 旧换证结果可能注销新登录，迟到同步覆盖认证状态 | Main 使用独立协调器进行代次检查；覆盖登录、登出、失败重试和并发交错 |
| 高 | 登出同步失败后错误标记已完成，后续不重试清理 | 区分未同步与已登出状态；失败继续重试 |
| 高 | 正在登录时仍以旧 applied 状态短路下一次刷新 | 登录同步开始前将 applied 标记为未知；增加 null/旧 token 交错测试 |
| 中 | 模型目录请求绕过系统/固定代理 | 统一 Main 请求传输层 |
| 高 | 单公钥永久缓存使 JWKS 撤销失效 | 仅保留 300 秒密钥集缓存；串行刷新并限制随机 kid 引起的远端刷新 |
| 高 | 自动入组没有继承默认成员预算/限流/模型策略 | 同一事务复制默认成员预算和模型范围，缺失模板拒绝并回滚 |
| 高 | Team 查询错误被跳过，可能将歧义多组误判为唯一授权组 | 查询失败时拒绝授权 |
| 中 | 新用户查询负缓存影响首次认证后续检查 | 创建后读取并填充正式用户缓存 |
| 高 | 轮换 master key 改变默认加密盐，既有模型密钥不可读 | 两实例显式共享稳定 LITELLM_SALT_KEY；说明保留旧加密材料 |
| 高 | 多 worker 使用独立内存限流计数 | 配置 Redis，供同一实例的 worker 共享 coordination 计数 |
| 中 | Nginx 默认连接容量不适合目标并发 | 显式设置 worker、连接数和文件描述符上限 |
| 高 | 管理脚本跟随重定向可能泄露管理凭据 | 禁止重定向，增加本地 HTTP 回归测试 |

另增加真实 RSA 签名的反例测试：错误签名、issuer、audience、过期、未来时间、
超长生命周期、缺失 jti/kid、账号不匹配及对称算法均不得进入用户授权/入组步骤。

## 验证及边界

- 301 项客户端相关测试、55 项服务端测试通过。
- TypeScript 检查、Lint、构建、Compose 配置校验通过。
- 数据库事务测试使用替身；本机 Docker daemon 不可用，尚未验证真实 PostgreSQL
  事务回滚/多进程首次入组、Redis 跨 worker 限流及真实 Jalor/JWKS 接口。
- 尚未完成千级并发压测；提高连接上限、共享计数不等于已验证吞吐能力。
- JWKS 删除公钥最多受 300 秒缓存影响；新 kid 最多受 5 秒刷新节流影响。
- Team 管理变更仍受 LiteLLM 授权缓存传播影响，不能承诺瞬时撤权。
- JWT 是 bearer token，不防止有效期内的窃取重放。客户端配置的生命周期上限
  不改变签发端实际有效期；客户端、Hook 与签发端必须配置一致。
- 删除用户记录不是封禁手段；有效组织身份会被视为新用户重新注册。
  封禁时保留用户记录并移除成员关系或放入 blocked Team。

以上说明区分代码审查结论与部署验收，不能将测试通过解释为生产环境绝对无问题。

## 双部署目录及集中配置复审

三个 Agent 对 `docker/`、`native/` 与 `src/config/` 进行第二轮审查，修复：

- 虚拟环境未激活时 Prisma 可执行文件不可见：安装与启动显式设置 PATH。
- 数据库初始化独立于请求进程；禁用自动 schema 同步，防止删除活动扩展列。
- Docker 文件路径加载 Hook 时 dataclass 导入崩溃：去掉延迟类型注解，使用独立进程调用上游加载器验证。
- 30–90 秒 JWT 每秒续期：监视器与换证缓存共用动态续期时点。
- 补充目录移动后的挂载路径测试、Linux 服务权限和管理操作说明。

本轮 357 项客户端相关测试、70 项服务端测试通过。native 安装/迁移测试使用替身，
未执行真实依赖安装、数据库迁移、容器启动或千级并发压测。

## 最新 dev 同步后复审

功能提交重放到最新 `dev` 后再次由三个 Agent 分域审查。审查发现退出时若 Gateway
原生配置热重载超时，旧进程会继续运行并可能在 JWT 剩余有效期内继续请求。现已改为
断开客户端并停止 Gateway，只有确认新配置已生效时才继续运行；对应回归测试覆盖热重载
成功与超时 fail-closed 两条路径。

同步后 Lint、TypeScript/Electron 编译、生产构建、Docker Compose 配置解析、332 项
客户端聚焦测试及 70 项 LiteLLM 服务端测试通过。完整 Vitest 在链接 worktree 中仍受
根工作区 PDF/KaTeX 依赖访问限制及缺少 OpenClaw runtime fixture 影响；这些失败与本功能
无关，相关测试已单独通过。

## 单实例认证适配

部署统一为一个 LiteLLM 服务及一个 config.yaml，移除 Nginx 分流和第二套实例配置。
启动入口安装固定适配，JWT 由自定义 Hook 返回认证主体，普通 Key 留给原生认证；
JWT 异常或无认证主体均禁止回退。新增测试覆盖实际 LiteLLM 原生认证管线中的管理 Key、
过期 Key、混合并发请求和共同授权入口，并验证不安全配置拒绝启动。
