# 原生协作试用说明

本轮将消息执行切换到 OpenClaw 原生 `sessions_send`。产品扩展只提供
`task_assistants`（发现、准备当前任务的助手会话）及 `assistants_create`
（按用户要求创建长期助手）。模型自主决定分工和发消息；界面不要求手工编组。

## 手动验证

在功能 worktree 运行 `npm run electron:dev:isolated`。它使用独立数据目录
`.work/multi-agent-preview`，避免与主目录应用共用会话数据。修改运行时补丁后
必须关闭这个开发窗口并运行 `npm run openclaw:runtime:win-x64` 重建。

1. 在设置中确认模型可用。需要新助手时，在「设置 → 助手」点击「新建助手」，填写名称和职责后保存；工作目录自动分配，保存后可编辑角色文件。也可以直接让主会话模型创建长期助手。首页不提供助手选择入口。
2. 新建主会话，输入：“请让研究助手提出一个小型待办应用方案，再让审阅助手指出问题，最后你汇总。请使用平级助手协作，不使用 Subagent。”
3. 主列表应只有一条用户会话；首次关联助手后右侧协作页自动展开。
4. 图上的节点查看该助手原生历史，箭头筛选消息方向，时间线查看具体消息。查看过程中主对话不切换。“已接收”不是工作完成。
5. 右键查看详情：显示成员原生用量的合计，点击成员查看独立统计和原生 ID。部分数据不可用有明确提示；不合并上下文占用率。
6. 导出明确限于主对话。协作任务不提供复制或分支，也不提供手工编组、交接、复制单一 ID 的重复菜单。
7. 删除会停止并清理本任务的成员会话，保留长期助手、项目文件和该助手的其他任务。失败时保留“删除未完成”状态，可重试；批量删除保留已成功项的结果。

## 实现与验证范围

原生发送前以真实 session/run/toolCall 校验任务归属，临时授予精确源、目标和原生
sessionId 的 send 能力；不开放其他任务的 history/list，也不把全局 visibility 改成 all。
消息本体和执行仍由 OpenClaw 保存和运行。SQLite 只记录成员、投递状态及删除进度。

自动化覆盖扩展绑定与权限、原生回执和回复轮次、跨任务拒绝、删除部分失败恢复、
批量部分成功、菜单、原生历史定位和部分统计。Electron 集成使用本地确定性模型服务，
验证了真实 Gateway 的主会话→助手→主会话、侧栏自动展开、消息定位、统计和删除；
这些结果不代表已验证任意外部模型的协作策略。

完整协作导出和协作复制不在本阶段提供。旧版本投递元数据仍可查看，模型工具目录不再暴露旧的 `collaboration_send`。
